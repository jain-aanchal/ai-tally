# Roadmap

The roadmap, its epics and their issues are managed in **Linear**, not in this repository and not in GitHub issues:

**[TALLY - AI Observability Platform](https://linear.app/cto-assist/project/tally-ai-observability-platform-269588d479e4)** (team CTO Assist, issue keys `CTO-*`).

This file is a pointer on purpose. A roadmap copied into the repo drifts from the one people actually update, which is how several scope docs here once said "not built" for features that had shipped (#342).

## Conventions

- **Epics** are Linear issues titled `[Epic] ...` in the TALLY project, with the work broken down as child issues.
- **Priority** carries the horizon: High for what is next, Medium for committed but later, Low for exploratory.
- **Design lives in the repo, tracking lives in Linear.** Specs and scope docs stay in `docs/` and `docs/specs/`; each epic links to its doc, and the doc does not carry a status line that could go stale.
- **Cite the Linear key** in commit messages, PR titles or code comments where a change implements an issue (for example `CTO-297`), as existing comments already do.
- **GitHub issues are not used for roadmap items.** Bugs found while working can be filed in Linear directly.
